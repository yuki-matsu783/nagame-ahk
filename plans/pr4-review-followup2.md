# PR #4 追加レビュー対応（テーブルの担当分離・AI返信の署名）

## Context

`3-開発フローを変える`（issue #3, PR #4）で、人間から「レビューした」との合図を受けたが、
`.claude/skills/issue-mr-flow/SKILL.md` の「レビュー完了合図の確認」節に従い `comments all` で
再確認したところ、**新たに未解決コメントが2件**見つかった（前回返信済みの1件とは別）。

1. `PRRT_kwDOT4Y-5s6ZfGIk`（`SKILL.md:43`、全体フロー旧行14）:
   「MRでレビュー・コメントする（人間）」と「対応完了コメントに返信する（`reply`）」が
   1行に混在しており、担当（人間／AI）を分けて記載してほしいという指摘。行8・9は既に
   同じパターンで分離済みであり、旧行14だけ分離されていなかった。
2. `PRRT_kwDOT4Y-5s6ZfGaK`（`SKILL.md:83`、`reply` サブコマンド節）:
   AIが`reply`で返信すると、GitHub上は返信者アカウントが元コメントの投稿者
   （`gh`認証ユーザー＝人間自身）と同一に見えてしまう。AIが返信したとわかるように
   表示できないか、という指摘。

指摘2について、`gh`/`glab` CLIは人間自身のアカウントで認証されているため、投稿者アカウント自体を
技術的にAI用の別人格へ切り替えることはできない（可能なのはbotアカウント等の別アイデンティティを
別途用意する方法のみ）。ユーザーに選択肢を確認した結果、**返信本文の先頭にAIであることを示す署名を
必ず付ける**方式を採用する（bot アカウント方式は、アカウント作成・PAT管理・認証切り替えの実装が
必要になり本PRの規模を超えるため見送り）。この判断は
`dev-tools/docs/spec/issue-mr-workflow.md` の既存の決定事項「`Add-MrThreadReply` の
`-ReplyBody` は関数側で定型接頭辞を付けない」と矛盾しない（関数はそのまま自由文を渡すのみで、
署名を含めるのは呼び出し側＝`reply` サブコマンドの運用ルールとする）。
