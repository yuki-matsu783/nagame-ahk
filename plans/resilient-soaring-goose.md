# Plan: worklogテンプレートの作成

## Context

`.claude/rules/docs-workflow.md` / `git-workflow.md` により、featureブランチでの実装時は
`worklog/日付_<planファイル名>.md` を作成し、試行錯誤を書き足していく運用になっている。
既存worklog（例: `worklog/20260815_fancy-painting-prism.md`）は毎回ゼロから書いており、
節構成（試したこと／うまくいったこと／ダメだったこと／次の一歩）を都度思い出す必要がある。
雛形を用意し、新規worklog作成時にコピーするだけで済むようにする。

## 実施内容

- `worklog/TEMPLATE.md` を新規作成する。
- 内容は既存worklog（`fancy-painting-prism.md`）の実際の節構成に合わせる:
  - タイトル行 `# worklog: <plan名>`
  - `対象:` / `plan:` の2行（プレースホルダ）
  - `## 試したこと` / `## うまくいったこと` / `## ダメだったこと` / `## 次の一歩` の4節
  - 各節はプレースホルダの説明のみ（実データは書かない）
- ファイル冒頭に、この雛形自体の使い方（コピーして`日付_<planファイル名>.md`にリネームする旨）を
  HTMLコメントで一言添える。

## 影響範囲

- 新規ファイル: `worklog/TEMPLATE.md` のみ。既存コード・ドキュメントへの変更なし。

## ブランチ運用について

`.claude/rules/git-workflow.md` により、実装フロー対象タスクはfeatureブランチ作成が原則だが、
本タスクはAHKアプリ本体の機能追加・既存動作変更ではなく、開発プロセス用の雛形ファイル1つを
追加するだけの軽微な変更のため、mainへの直接コミットを想定する（ユーザーの指示があればブランチを切る）。

## 検証方法

- 作成した `worklog/TEMPLATE.md` を目視で確認し、既存worklogファイルと節構成が一致していることを確認する。
