# 全体フロー16〜18のタスク分解（レビュー指摘対応）

## Context

PR #4 に新規の未解決レビューコメントが1件付いた（`threadId=PRRT_kwDOT4Y-5s6ZgH95`,
`.claude/skills/issue-mr-flow/SKILL.md:47`、現行の全体フロー行18）。指摘内容は、
「他タスクと同様にcommit,pushをエージェント、レビュー・コメントを人間、レビュー内容を取得し
AIアセットを修正。対応が完了したら返信を繰り返す、というタスクに分解すること」。

現在の全体フロー16〜18は以下のように「commit,push」（エージェント作業）と「レビュー」
（人間作業）が1行に混在している：

```
| 16 | 設計反映: ... | エージェント |
| 17 | AIアセット改善: ... | エージェント |
| 18 | commit, push → レビュー（16〜18を合意まで繰り返す） | エージェント＋人間 |
```

一方、同じレビューループを扱う8〜9行目・14〜15行目は既に「担当が1人（人間 or サブコマンド）に
閉じる行」に分割されており、今回の指摘はこの既存パターンに16〜18も揃えるよう求めている
（実際、過去に一度この「担当混在」の問題は14行目で発生し、8/9と同じパターンへ分割済み
（HANDOFF.md記載の過去対応）。今回18行目でも同種の指摘が再発した形）。

## 実施内容

`.claude/skills/issue-mr-flow/SKILL.md` の全体フロー表・関連する行番号参照を、8/9・14/15と
同じパターンに合わせて分割する。

1. **全体フロー表（16〜21行目）を5行→7行に再構成**（既存の8/9・14/15パターンを踏襲）:
   ```
   | 16 | 設計反映: plans/worklogの内容をdocs/spec, docs/adrへ反映する | エージェント |
   | 17 | AIアセット改善: 気付いたルール・スキルの不備を反映する | エージェント |
   | 18 | commit, push する | エージェント |
   | 19 | MRでレビュー・コメントする | 人間 |
   | 20 | レビュー内容を取得し、設計反映・AIアセットの内容を修正する。対応が完了したコメントには
        対応内容を返信する（16〜20を合意まで繰り返す） | `comments` / `reply` |
   | 21 | plans/ worklog/ を削除し、HANDOFF.mdを次タスクへリセットする | エージェント |
   | 22 | commit, push する | エージェント |
   | 23 | マージする（squash merge。ブランチは削除してよい） | 人間 |
   ```
   （旧19〜21が新21〜23へ2つ後ろにずれる）

2. **ステップ番号を参照している箇所を新番号に更新**（SKILL.md内）:
   - `resume` サブコマンド節: 「全体フロー21ステップ」→「全体フロー23ステップ」
   - 「レビュー完了合図の確認」節見出し: 「全体フロー9・15・18」→「全体フロー9・15・20」
     （本文中の「16〜18」等の言及があれば同様に「16〜20」へ）

3. **`dev-tools/docs/spec/issue-mr-workflow.md`**: 「全体フロー21ステップ」→「23ステップ」
   （resume節、`resume`が判断材料にする全体ステップ数の記述）。

4. **`HANDOFF.md`**: 「次回やること」の「合意後、全体フロー19〜20:」を「全体フロー21〜22:」に
   更新する（現行の次アクションの参照先のみ。過去の出来事を記録した既存の記述は史実として
   そのまま残す）。また「現在地」に今回の対応（レビュー指摘・分解内容）を追記する。

5. **`reply` サブコマンドで返信**: `Get-MrForBranch` でMR番号を取得済み（#4）。
   `Add-MrThreadReply -MrNumber 4 -ThreadId "PRRT_kwDOT4Y-5s6ZgH95" -ReplyBody <署名付き対応内容>`
   で、分解した旨を返信する（署名は `Claude Codeより:` を先頭に付与。SKILL.mdの`reply`手順どおり）。

worklogは今回新規に `worklog/20260815_quiet-drifting-lantern.md` を作成し、経緯を記録する。

## 対象外

- 8〜15行目（既に分割済みで指摘対象外）のパターン自体の変更。
- ステップの実処理（`Provider.ps1` 等）の変更。今回はSKILL.md/spec文書の表記・番号整合のみ。
- worklog/plansの過去ファイル（他タスクの分）への手入れ。

## 検証方法

- 変更後のSKILL.md全体フロー表を通読し、1〜23が連番で欠落・重複なく、各行の担当が単一
  （人間 / エージェント / サブコマンド）になっていることを確認する。
- `grep -n "全体フロー\|21ステップ\|23ステップ"` でSKILL.md・spec文書内の参照が新番号に
  揃っていることを確認する。
- `reply` 実行後、`comments all` で該当スレッドに返信が反映されていることを確認する
  （スレッド自体はレビュアーが解決するまでunresolvedのまま残る仕様のため、解決確認は不要）。
