# 再発防止ルール化: ExitPlanModeでの計画内容とりちがえ

## Context

本セッションで、`ExitPlanMode`の`plan`引数に**古い（既に承認・実行済みの）計画テキストを、
新しい計画のつもりで3回連続で誤送信する**という事象が発生した。直前に対象ファイルをReadしてから
即座に転記する、という対策を講じても再発した。実害（誤った書き込みやコマンド実行）はなかったが、
プロセス上のリスクが高いため、ユーザーの指示によりこれをAI向けルールとして明文化し、再発防止を図る。

原因分析（会話内で実施済み）の要点:
- 同じ見出し構成（Context/実施内容/対象外/検証方法）の長文が会話履歴内に複数回出現すると、
  出現回数の多い方（＝古い内容）に生成が引っ張られる。
- `ExitPlanMode`は長文をテキストとして丸ごと引数に渡す仕様であり、機械的なコピーではなく
  実質的な再生成になるため、上記の混同が起きやすい。
- 「気をつける」という意図レベルの対策では再発を防げなかった。

## 実施内容

`.claude/rules/plan-mode-safety.md` を新規作成し、`CLAUDE.md`の「Claude Code固有ルール」
（現在空）から参照する。ルールの骨子:

1. **plan引数は要約に留める**: `ExitPlanMode`の`plan`引数には全文を逐語転記せず、
   要点を要約した短いテキストを渡す（詳細はplanファイル本体を正とする）。長文の丸ごと再生成は
   会話履歴内の類似テキストとの混同リスクを高めるため避ける。
2. **同一セッション内で複数回計画を立てる場合、計画ごとに新しいplanファイル名を使う**
   （`docs-workflow.md`の「plansは手動で使い回さない」方針とも整合。既存の承認済み
   plansファイルを上書きしない）。
3. **提出前セルフチェック**: `ExitPlanMode`呼び出し直前に、`planFilePath`が今回のタスク用の
   ファイルになっているか、`plan`引数の主題（ファイル名・見出し）が直前に書いた/読んだ内容と
   一致しているかを一言で確認してから送信する。
4. **異常検知時の振る舞い**: `ExitPlanMode`の返り値（Approved Planのエコー）が意図した内容と
   異なっていた場合、同じ操作を再試行して「気をつける」だけで済ませず、直ちに作業を止めて
   ユーザーに状況を報告する。必要であれば、ツール経由の長文再現に頼らず、計画本文を通常の
   チャットメッセージとして直接提示し、人間の明示的な確認を得てから実装に進む。

## 対象外

- `ExitPlanMode`ツール自体の実装変更（Claude Code本体の話であり本リポジトリの管轄外）。

## 検証方法

- `.claude/rules/plan-mode-safety.md` が作成され、`CLAUDE.md`の「Claude Code固有ルール」から
  参照されていることを確認する。
- 内容が簡潔で、次回同種の作業時にすぐ参照・実行できる粒度になっていることを確認する。
