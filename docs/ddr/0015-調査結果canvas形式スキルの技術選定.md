# 0015. 調査結果canvas形式スキルの技術選定

## 背景

issue #58: issue #48で確立した`reports/<plan名>.html`（TailwindCSS CDN方式の自己完結HTML）は
一覧・表形式を前提としており、複数要素間の関連・依存関係を主題とする調査結果ではこの表現が
読み取りにくいという課題があった。codecanvas.appのようなノード・エッジによるcanvas形式が
有効であることを、issue #48の対話中の比較試作（TailwindCSS CDN通常版・自前ミニマムCSSハイブリッド
版・リッチ演出版・canvas版）で確認した。issue #58ではこれをスキル（`.claude/skills/canvas-report/`）
として新設し、ユーザー要望によりノード・エッジの表現の幅（アイコン・形状・色・エッジスタイル・
方向・ラベル・グルーピング）、参照ハイライト、ミニマップ、詳細表示（markdown/mermaid）、
連続セマンティックズームを盛り込んだ。

## 決定

- **canvas-reportスキルを新設し、ノード・エッジで構成されるcanvas形式のHTMLテンプレートを
  提供する**。判断基準（調査結果が複数要素間の関連・依存関係を主題とするか）を`SKILL.md`に
  明文化し、AIエージェントが調査結果の性質に応じてTailwindCSS CDN通常版とcanvas版のどちらを
  使うか判断する。
- 表現方式は**TailwindCSS CDN + 素のJS/SVGの範囲に留める**（D3.js等のグラフ描画専用ライブラリは
  導入しない）。ノードの形状（`clip-path`）・アイコン（絵文字）・サイズ（被参照数連動）、
  エッジの色・線種・太さ（関係カテゴリ連動）、グルーピング（外接矩形計算によるクラスタ枠）は、
  いずれもこの範囲内で実現できることを実データ（nagame-ahkの`src/features/`・`src/lib/`の
  実際の依存関係、14ノード・21エッジ）で検証済み。
- **markdown相当の説明文（`detailHtml`）は、AI生成時にHTMLへ事前変換する**方式を採用し、
  marked.js等のクライアント側markdownパーサは追加しない。
- **mermaid図の描画には、mermaid.jsをCDN経由で追加する**（TailwindCSSに続く2つ目の外部CDN
  依存として許容する）。
- **ズーム操作は、`scale`の連続値に応じてノードの詳細度をicon/compact/detailの3段階で自動的に
  切り替える「連続セマンティックズーム」方式を採用する**。detail段階への昇格時のみ
  `mermaid.run()`を呼び、近接ノードのカードが重なる場合はz-indexによる前面表示を許容し、
  力学的な自動レイアウト調整は行わない。クリックでの詳細パネル表示も、ズームせず1ノードを
  じっくり見たい場合のショートカットとして併用する。

## 却下した案

- **クリックで詳細パネルを開く方式への単純化**: 実装コスト・レイアウト崩れリスクの低さから、
  調査結果作成の初期段階ではこちらを採用していた。しかしユーザーから「本格的な連続セマンティック
  ズームを検討し直したい」との要望があり撤回した。
- **力学的な自動レイアウト（ノード重なり回避のための座標自動調整）**: detail段階でカードが
  拡大した際の近接ノードとの重なりを、座標を自動的に押し出して回避する案。実装コストが高く、
  「ユーザーはパン操作で見たいノードへ寄せられるため実用上の支障は小さい」と判断し不採用とした。
- **markdown文字列をクライアント側でパースする方式**（marked.js等）: `reports/<plan名>.html`が
  push単位で作り直され、squash merge後は削除される使い捨てドキュメントである
  （`.claude/rules/docs-workflow.md`参照）ため、外部ライブラリを追加するコストに見合わないと
  判断し不採用とした。
