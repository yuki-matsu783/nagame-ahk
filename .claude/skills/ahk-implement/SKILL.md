# nagame-ahk 実装フロー

このスキルは `CLAUDE.md` の「実装フロー（必須）」を実行手順に落とし込んだものです。
`nagame-ahk` で新機能の追加・既存動作の変更を行うときは、必ずこの手順で進めてください。
コーディングの詳細ルール（命名規則、v2固有の注意点など）は `CLAUDE.md` を参照します。

## 手順

### 1. 設計ドキュメントを作成する

- `docs/機能名.md` を新規作成する。
- 既存の `docs/*.md`（例: `docs/activity-status.md`, `docs/logger.md`）と同じ章立てに揃える:
  - 背景・目的
  - 仕様（動作・UI・ホットキー等）
  - 影響範囲（追加・変更するファイル）
  - 設定項目（`Settings` への追加値）
  - 未決定事項・懸念点

### 2. 人間の承認を得る

- 作成した設計ドキュメントの内容をユーザーに提示する。
- **明示的な承認を得るまでコードの実装には着手しない。**
- 修正依頼があれば設計ドキュメントを更新し、再度確認を取る。

### 3. 実装する

- `CLAUDE.md` のコーディングルール（命名規則、v2固有ルール、`#Include` 順序、エラーハンドリング等）に従う。
- 機能のエントリポイントとなるファイルの冒頭に、設計ドキュメントへの参照コメントを入れる。
  ```ahk
  ; 設計: docs/機能名.md
  ; （ファイルの役割を1〜2行で記述する）
  ```
- エラーが起こりうる処理は `try/catch` ＋ `Logger.Error` で囲み、原因究明用に要所へ `Logger.Debug` を仕込む。

### 4. 整合性を維持する

- 実装中に設計と異なる判断をした場合は、設計ドキュメント側も合わせて更新する。
- ソースコード側の参照コメントのパスも、ドキュメントのリネーム等に追従させる。
