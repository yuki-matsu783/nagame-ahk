# コーディングルール（AutoHotkey v2）

## 基本

- 全スクリプトの先頭に `#Requires AutoHotkey v2.0` を記述する。
- 文字コードは **UTF-8 (BOM無し)** で保存する。AutoHotkey v2 はBOMの有無に関わらずスクリプトをUTF-8として解釈するため、BOMは不要。ただし `FileAppend` 等でファイルへ書き出す際に `"UTF-8"` を指定するとBOM付きで生成される点には注意する（stdoutなど繰り返し書き込む対象では `"UTF-8-RAW"` を使いBOMの混入を避ける）。
- 改行コードは LF。
- インデントは半角スペース4つ。タブは使用しない。
- 波括弧は行末に置く（K&Rスタイル）。

```ahk
MyFunc(x) {
    if (x > 0) {
        return true
    }
    return false
}
```

## 命名規則

- 関数・クラス名: `PascalCase`（例: `GetWindowTitle`, `class HotkeyManager`）
- ローカル変数名: `camelCase`（例: `windowTitle`, `retryCount`）
- 定数・設定値: `config/Settings.ahk` 内で `class Settings` の静的プロパティとして `PascalCase` で定義する（AHK v2 に `const` 修飾子は無いため、「Settings クラス以外から書き換えない」運用ルールとする）。
- グローバル変数は極力使わない。状態を持たせる場合はクラスの静的プロパティにまとめる。

## v1との違いに関する注意（v2固有ルール）

- 全ての関数呼び出しは括弧必須。レガシーなコマンド構文（`MsgBox, text` のようなカンマ区切り）は使用しない。
- 代入は `:=` を使う。式中の `=` は大文字小文字を区別しない比較演算子であり代入ではないため、混同を避けるため比較には明示的に `==`（大文字小文字を区別）を使う。
- コレクションは `Map()` / `Array()` を明示的に使う。素の `{}` はプロパティアクセス用のシンプルなオブジェクトに限定し、キーを動的に列挙する用途では `Map()` を使う。
- 無名関数・短いコールバックはファットアロー `(*) => Expr` を使う。
- ホットキーはできる限り `#HotIf` でコンテキスト（アクティブウィンドウ等）を絞り、グローバルに常時有効なホットキーは最小限にする。
- クラスの `static` メソッドをコールバック（`SetTimer` / `HotKey` / `Menu.Add` / `OnEvent` 等）として渡すときは、`ClassName.MethodName` のように**裸で参照しない**。裸参照は暗黙の `this` 引数を要求する未束縛の `Func`（`MinParams` が1以上）になり、引数0個で呼び出す `SetTimer` 等では `"Invalid callback function"` エラーになる。必ず `(*) => ClassName.MethodName()` のようにファットアローで包む。
- `SetTimer` を無効化する（`SetTimer(callback, 0)`）ときは、開始時に渡したコールバックと**同一のオブジェクト**を渡す必要がある。呼び出すたびに新しい `(*) => ...` を作ると別オブジェクト扱いになり停止できないため、コールバックは `static` プロパティとして1つ保持し、開始・停止の両方でそれを使い回す。

## エラーハンドリング

- 外部リソース（ファイル、ウィンドウ操作、レジストリ等）にアクセスする処理は `try/catch` で囲み、失敗時は `lib/Logger.ahk` 経由でログに残す。
- 空の `catch` は禁止。最低限 `catch as e { Logger.Error(e.Message) }` を書く。
- エラー発生時に原因究明が容易になるよう、`catch` 内では `Logger.Error` に加えて、関連する変数の値や処理直前の状態を `Logger.Debug` で残す。
- 正常系でも、外部呼び出しの前後や分岐条件など判断のポイントには `Logger.Debug` でログを残す。本番運用時のログ量は `Settings.LogLevel` を `INFO` 以上にすることで抑制する。

## コメント

- 各ファイル冒頭に、そのファイルの役割を1〜2行で記述する。
- 複雑なホットキー・正規表現・座標処理には「なぜそうしたか」を残す（「何をしているか」はコードで表現する）。
- コメントは日本語で統一する。
- レビュー容易性を上げるため、対応する設計ドキュメントを持つファイル（クラス/機能のエントリポイント）の冒頭コメントに、そのドキュメントへのパスを記載する。ソースコードと設計が常に紐づくようにし、レビュアーが実装と設計を照合しやすくする。
  ```ahk
  ; 設計: docs/spec/機能名.md
  ; （ここに、そのファイルの役割を1〜2行で記述する）
  ```
- 設計ドキュメントを更新した場合は、参照しているコメント側のパスも追従して更新する。

## #Include

- `main.ahk` からの `#Include` は次の順序を守る: `config` → `lib` → `core` → `features`
- 循環参照が発生する構成にしない（`features` → `core` → `features` のような依存は禁止）。

## GUI・トレイ

- ユーザー向けの文言（トレイメニュー、MsgBox 等）は日本語で統一する。
- GUIを追加する場合は `features/` 配下にサブフォルダを切り、`Show()` / `Close()` を持つクラスとして実装する。

## Git

- ビルド成果物（Ahk2Exe で生成した exe 等）やログファイルはコミットしない（`.gitignore` で除外済み）。
