issue #54 調査結果

extract-frontmatter.shをgitignoreを読み取って対応するようにする

plan: plans/reflective-zooming-cake.md ／ 対象: .claude/scripts/src/extract-frontmatter.sh

背景・問題

extract-frontmatter.sh は find "$target_dir" -type f -name '*.md' で再帰走査するが、.gitignore を 一切考慮しない。参考ディレクトリ/ （外部OSSのローカルclone置き場、.gitignore対象）のような大量markdownを含むディレクトリまで 走査対象になり、issue #43対応時には「リポジトリルート一括実行が2分以上かかりタイムアウトし、 index.jsonlが壊れた状態で残る」 という既知の問題として記録されていた。

検証した2方式

観点 方式A: git ls-files ベースに置き換え 方式B: find維持 + git check-ignore で事後フィルタ
実装 git ls-files --cached --others --exclude-standard -z -- "$target_dir" | grep -z '\.md$' | sort -z find ... -print0 | git check-ignore --stdin -z -v
正しさ（ignore対象の除外） ✓ 完全に除外 ✓ 完全に除外
根本課題（走査コスト）の解消 ✓ ignore対象を走査自体しない ✗ findが参考ディレクトリ配下を全訪問
既存出力フォーマットとの互換性 concept_id/directory/frontmatter/mtime が既存版とバイト単位で完全一致 同左（未採用のため参考値）
既存テストへの影響 無し（main()内の走査行のみの変更） 無し（同上）
結論 採用 不採用

性能面の実測（参考ディレクトリ配下に3,000件のダミーmarkdownを追加）

find（現状）

3,005 件を訪問

所要時間 約0.94秒

git ls-files（方式A）

2 件を訪問

所要時間 約0.54秒

この規模での体感差は小さいが、既存の懸念点が指摘する「巨大な外部OSSクローン」規模ではこの差が 支配的になる。加えて現状版は候補ファイルごとに jq プロセスを起動するため、候補ファイル数を減らせる効果は件数差以上に大きいと考えられる。

結論

方式A（git ls-files --cached --others --exclude-standard ベースへの置き換え）を採用する。既存の出力フォーマット・単体テスト への影響は無く、issue #43由来の走査コスト問題も根本解消できる。作業計画では、この置き換えに 加え、docs/spec/extract-frontmatter.md の該当箇所の更新と、走査方式に関する新規DDR追加をあわせて実施する。
